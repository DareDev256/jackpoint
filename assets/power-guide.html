power-user guide

Your AI Toolkit, Mastered

How to actually get more done with Claude Code, Gemini, Qwen and the rest. Real workflows, hooks, skills, and MCPs. No fluff.
01 · PHILOSOPHY

These Are Agents, Not Chat

You've got four AI tools now. Each one is a worker, not a conversation partner. Stop thinking of them as chatbots and start thinking of them as interns who actually work.

The Mindset Shift

Instead of "write me an email," you say:

  • "Draft a 3-sentence follow-up email to Sarah about the Tuesday meeting"
  • "Review the code in `src/payment.js` for security issues"
  • "Delete all `.jpg` files older than 2020 in my Downloads folder"

The difference: specificity and delegation. When you're specific about what you want and why, Claude (especially Claude Code) can actually do the work, not just suggest it.

The Work Cycle

  1. Brief it: "Here's the task, deadline, and constraints."
  2. Let it work: Don't interrupt. Don't second-guess. Let it make mistakes and fix them.
  3. Review once: Look at what it did. Say "ship it" or "here's what's wrong."
  4. One fix pass: Let it correct itself. Then you're done.

The worst mistake: treating AI like a search engine. You don't need "Tell me how to write a Python script." You need "Write a Python script that reads a CSV and flags rows where column 3 > $5000." Then it goes and does it.

02 · TOOLING

The Right AI for the Right Job

You have four tools. They overlap. Here's how to pick.

Tool Best For Speed Cost When to Use
Gemini (free) Quick questions, summaries, brainstorming Fast Free Daily questions. Don't overthink it.
Claude Code Code, files, projects, real work Slow-medium Per-use Anything that involves reading/writing files or running commands
Qwen (local) Private work, sensitive stuff, offline Medium Free (runs on your Mac) Client data, passwords, confidential brainstorms
Ollama (local) Coding, math, structured output Medium Free (local) When you want to stay offline and fast

The Decision Tree

Ask yourself:

  • Does it involve files or code? → Claude Code
  • Is it sensitive / confidential? → Qwen or Ollama (offline)
  • Just a quick question? → Gemini
  • Is your internet down? → Ollama or Qwen
  • Need it now and it's simple? → Gemini

Real Example

"I need to extract email addresses from a CSV file, check if they're valid, and flag duplicates."

  • Claude Code → reads CSV, writes script, runs it, shows you results ✓
  • Gemini → can explain how, but won't actually do it
  • Qwen → could work, but slower than Claude

Answer: Claude Code.

03 · CLAUDE CODE CORE

Claude Code's Three Superpowers

Superpower #1: CLAUDE.md (Your Personal Operating Manual)

Create a file called CLAUDE.md in your project folder. This file tells Claude how you work and what you care about.

What goes in CLAUDE.md?

  • How you like code formatted (spaces vs tabs, naming conventions)
  • Tools you always use (npm, pytest, Docker, etc.)
  • Folders and structure ("source code lives in src/, tests in tests/")
  • Commands to build/test ("run npm test before committing")
  • What NOT to do ("never push directly to main")
  • Common shortcuts and preferred libraries

Example CLAUDE.md:

# Project: My Investment Tracker ## Build & Test - Build: `npm run build` - Test: `npm test` - Format: `npx prettier --write .` - Always test before committing. ## Code Style - 2-space indents - camelCase for variables - Use async/await, not .then() - React hooks, not class components ## Folder Structure - `/src` — React components - `/src/api` — API calls - `/tests` — Jest tests - `/docs` — Documentation ## Architecture - All API calls go through src/api/client.js - State lives in Zustand, not Context - Never store passwords or API keys in code ## Before Pushing - All tests pass - Run npm audit (fix warnings) - Update CHANGELOG.md

Why this matters: Claude learns these rules and follows them in every session. You never have to re-explain.

Pro tip: Keep CLAUDE.md under 200 lines. Longer files consume tokens and Claude may not follow them as reliably. If you've got a lot to say, break it into rules files inside .claude/rules/.

Superpower #2: Slash Commands

In Claude Code, type / and you'll see a menu of commands. Here are the essentials:

  • /help — Show all available commands
  • /init — Claude auto-generates a CLAUDE.md for your project by reading your code
  • /memory — View and edit your project memory (what Claude has learned about your project)
  • /plan — Claude outlines a multi-step plan before starting work
  • /review — Claude reviews code you've changed for bugs and quality
  • /mcp — See and manage your connected tools (MCP servers)
  • /loop — Repeat a task every N seconds/minutes (useful for polling)

Most useful for you: /init, /memory, and /plan.

Superpower #3: Auto Memory (Claude Learns As You Work)

You don't write everything down. Claude Code watches you and learns:

  • How to build your project
  • Where bugs usually hide
  • What you keep correcting it on
  • Tools and libraries you prefer

It saves these as plain-text files you can read/edit:

~/.claude/projects/<your-project>/memory/ ├── MEMORY.md # Index (loaded every session) ├── debugging.md # Debugging patterns it's learned └── patterns.md # Code patterns you use

Run /memory to browse what it's learned. If it's wrong, edit it. If it's right, leave it.

Why auto memory is powerful: You spend less time re-explaining yourself. Claude gets smarter every session. And it's all plain text, so you can read it and fix it anytime.
04 · MCPs

MCPs: Give Claude Access to Your Tools

MCP stands for "Model Context Protocol." In plain English: it's a connector that gives Claude access to things outside of Claude.

Without MCPs: you copy data into chat. With MCPs: Claude reads it directly.

What MCPs Can Connect To

  • Google Drive, Slack, Gmail, Notion, Jira
  • GitHub, GitLab
  • Databases (PostgreSQL, MongoDB)
  • APIs you build yourself
  • File systems on your computer
  • Calendar, contacts

How to Add an MCP

Step 1: Find one at the Anthropic Directory or just ask "are there MCPs for Slack?"

Step 2: Add it with one command

# Add a GitHub MCP (to help Claude review code in GitHub) claude mcp add --transport http github https://api.githubcopilot.com/mcp/ \ --header "Authorization: Bearer YOUR_GITHUB_TOKEN" # Add a local Slack MCP (to let Claude read Slack channels) claude mcp add --transport http slack https://mcp.slack.com/mcp \ --header "Authorization: Bearer YOUR_SLACK_TOKEN" # Add a local stdio server (runs a script on your machine) claude mcp add --transport stdio local-db -- python3 /path/to/db-server.py

Step 3: Use it

Once added, Claude automatically discovers what it can do. You just ask naturally:

"Show me all GitHub issues with the label 'bug' from the last 7 days" "Find all Slack messages from this week that mention 'urgent'" "List all customers in the database who haven't paid an invoice"

5 MCPs Every Non-Techie Should Know

MCP What It Does Best For
GitHub Claude reads your GitHub repos, reviews code, creates issues Code review, managing projects
Slack Claude reads Slack channels, can summarize discussions Staying on top of team chat without reading everything
Google Drive Claude reads docs, sheets, slides Working with shared documents without copy/paste
Jira Claude reads issues, can create/update them Task management without switching apps
Sentry Claude monitors your app's errors Debugging crashes, finding patterns in errors
Find your token: Most MCPs need an authentication token. For GitHub, go to github.com/settings/personal-access-tokens and create one. For Slack, go to api.slack.com/apps. The Anthropic Directory shows you exactly where to get one for each MCP.
Security note: Don't paste tokens into chat or save them in plain text. Store them safely, then only paste them once into the claude mcp add command.
05 · HOOKS

Hooks: Automate What Should Be Automatic

Hooks are commands that run automatically at specific moments. They let you enforce rules without Claude having to think about them.

When Hooks Run

  • Before a file is edited: Validate it, check permissions
  • After a file is edited: Auto-format it, lint it
  • Before a commit: Run tests, check for secrets
  • After a commit: Deploy, notify Slack
  • When Claude needs input: Show a notification

Safe, Simple Example: Auto-Format After Every Edit

Say you want code auto-formatted every time Claude edits a file. Add this to your .claude/settings.json:

{ "hooks": { "PostToolUse": [ { "matcher": "Edit", "hooks": [ { "type": "command", "command": "npx prettier --write ." } ] } ] } }

What this does: After Claude edits a file, Prettier auto-formats it. No thinking. Just happens.

Another Example: Notify You When Claude Waits

You don't want to watch the screen. Add a hook that notifies you when Claude needs input:

{ "hooks": { "Notification": [ { "type": "command", "command": "osascript -e 'display notification \"Claude needs your input\"'" } ] } }

Now macOS will pop a notification. Your phone buzzes. You're not stuck watching.

Keep hooks simple and safe. Hooks run automatically, so a broken hook can break your workflow. Test it manually first. Start with read-only stuff (checking files, sending notifications) before doing write/delete operations.
Hooks are advanced. Don't obsess over them early. Master CLAUDE.md and MCPs first. Hooks are for when you've done the same thing three times and you're tired of it.
06 · SKILLS

Skills: Reusable Instructions

A skill is a packaged set of instructions that you or Claude can invoke with a slash command.

Built-in Skills You Already Have

  • /code-review — Review code for bugs and quality
  • /debug — Systematic debugging
  • /help — Help on any Claude Code feature
  • /verify — Verify that a change actually works

Create Your Own Skill

Say you always ask Claude to "check this file for spelling and grammar." Make a skill so you can just say /proofread.

Step 1: Create the skill file

# Create this file: .claude/skills/proofread/SKILL.md # Proofread Review the text for: - Spelling errors - Grammar mistakes - Unclear sentences - Redundant phrases - Tone (is it professional? friendly? angry?) If you find issues, list them clearly and suggest fixes. Never rewrite the whole thing unless asked.

Step 2: Use it

/proofread Here's my email to the client. Can you check it?

Claude runs the skill and reviews your email.

When to make a skill:
  • You find yourself pasting the same instructions repeatedly
  • You have a multi-step checklist you want Claude to follow
  • You want to share a workflow with someone else
Don't make a skill for a one-time task. That's what conversation is for.
07 · WORKFLOWS

How to Actually Get Things Done

The Claude Code Workflow

  1. Create a folder for the project (e.g., ~/my-project)
  2. Write or create a CLAUDE.md in the root (or run /init to auto-generate one)
  3. Brief Claude clearly: "Do X, which involves Y, and we need it by Z"
  4. Let it work — don't interrupt. If it's stuck, you'll see it
  5. Review what it made — files, code, output, all visible
  6. Give one round of feedback — "this is wrong, fix it" — then let it fix it
  7. Done. You review one more time and ship.

Pattern: "I Have a Folder of Files"

Scenario: You have 200 photos and want to rename them all with dates.

How to brief Claude:

I have a folder at ~/Photos/2024-12-15 with 200 image files. They're named IMG_1234.jpg, IMG_1235.jpg, etc. I want them renamed to PHOTO_2024-12-15_001.jpg, _002.jpg, etc. Write a script that does this and run it. Then show me the first 5 new filenames.

Claude will: read the folder, write a script, run it, show you the results. One request. Done.

Pattern: "I Want This Automated"

Scenario: Every Friday morning, you want a summary of GitHub issues created this week.

How to brief Claude:

I want a script that runs every Friday at 8 AM. It should fetch all GitHub issues from this week in my repo. Group them by label (bug, feature, question). Email me a summary with: count per label, list of titles. Use the GitHub MCP I have connected. Write the script and set up the schedule.

Claude will write the script and schedule it (or tell you how to if you need manual steps).

Pattern: "This Code Is Broken"

Scenario: Your app crashes on startup and you don't know why.

How to brief Claude:

My app crashes on startup. Here's the error message: [paste error] Go through the code and find the root cause. Then fix it and verify it works.

Claude will trace through the code, find the bug, fix it, run it. Done in minutes instead of hours.

Efficiency Habits

  • Be specific. "Fix the login bug" vs. "When users paste an email with spaces, the login endpoint rejects it as invalid. Fix this and test it."
  • Let it run. Don't say "wait, maybe try this instead." Give it one direction, let it complete.
  • Use a project folder. Keep related files together. CLAUDE.md lives in the root. Everything else is nearby.
  • Review the code. You don't have to understand every line, but you should know if it looks reasonable.
  • Test manually once. After Claude fixes something, click it, run it, make sure it works as expected.
  • Commit with messages. If Claude made changes, commit them with a message so you have a record.
08 · NEXT LEVEL

Where to Go Deeper

Official Documentation

  • Claude Code Docs: code.claude.com/docs — Full reference. Includes all slash commands, settings, advanced features.
  • MCP Directory: claude.ai/directory — Browse integrations you can connect.
  • Agent SDK: If you want to build custom AI agents (advanced), see platform.claude.com.

Features to Explore Later

  • Sub-agents: Spawn multiple Claude agents working in parallel on different parts of a task
  • Path-scoped rules: Different CLAUDE.md rules for different folders
  • Plugins: Packaged extensions for Claude Code (like npm packages, but for AI)
  • Routines: Schedule Claude tasks to run on a recurring schedule
  • Desktop app: Visual diff viewing, multiple sessions side-by-side

When You Get Stuck

  • Run /help in Claude Code for the built-in help
  • Check code.claude.com/docs for the exact feature you need
  • Ask Claude itself: "How do I [thing]?" — it often knows
  • Most importantly: start small. CLAUDE.md → MCPs → Hooks. Don't try everything at once.

Advanced But Worth Knowing

  • Settings file precedence: You can have global settings (~/.claude/settings.json) and project settings (.claude/settings.json). Project settings override global.
  • Environment variables: You can set env vars that Claude Code sees, useful for API keys and configuration
  • Permissions: You can whitelist or blacklist which commands Claude is allowed to run (security feature)
  • Custom MCP servers: If you write code, you can build your own MCP server that Claude talks to

Five-Minute Startup Checklist

New project? Do this:

  1. Make a folder for the project
  2. Run claude to start
  3. Run /init to auto-generate CLAUDE.md
  4. Read and tweak CLAUDE.md (add any special rules)
  5. Commit CLAUDE.md to git if it's a team project
  6. Done. Ready to work.

Common Mistakes (Avoid These)

  • Not being specific. "Fix this" is too vague. "The login page shows a 404 when I paste @example.com" is clear.
  • Interrupting Claude while it's working. Let it finish. If it's genuinely stuck (5+ min with no output), then say something.
  • Not using a project folder. Keeping related files scattered makes Claude's job harder. Group by project.
  • Forgetting CLAUDE.md exists. Every time you explain something twice, add it to CLAUDE.md so it's remembered.
  • Pasting tokens into chat. Use claude mcp add to add auth securely, not by pasting in the conversation.
  • Ignoring auto memory. It learns as you go. Check it now and then. It gets smarter.

You now have the tools and knowledge to work 3x faster.
